# E 的运输、凝胶与正式联网交接单 v0.6

更新日期为 2026-11-22。E 使用 **Codex Agent**，负责车辆与货物物理、门闩、鸡与笼体、凝胶、路线与关卡组装、订单、燃油、三个特殊事件及翻车恢复。E 负责正式建房与连接、房主端裁决、状态同步和断线处理，统一接入共享 C# 声明、正式主场景和工程级设置。B 确认规则和接口语义，D 提供人物模块、本地输入和玩家侧反馈。以下为开发与实际验收规格。[灰盒设计 v0.5](../灰盒设计_v0.1.md) · [API 与联调契约 v0.6](../API与联调契约_v0.2.md)

## 2. 几何、货物与布局

三维代理按宽 X × 高 Y × 长 Z，Y 向上、前方 −Z。整车 3.00 × 3.50 × 8.80 m，轮胎等计入最大外宽。后舱净 2.70 × 2.68 × 5.80 m，地板顶高 0.70 m，顶棚厚 0.12 m。隔断净门 1.10 × 1.90 m、后门 1.80 × 2.00 m，后斜板宽 1.80 m、水平伸出 2.10 m，轴距 5.80 m。道路总净宽 6.00 m，弯道中线半径 20 m 为初值，允许全幅行驶，按实际车控检查扫掠并按需要布置灰盒的避车空间。

| 配置 ID | 临时试装几何 | 状态与验证 |
|---|---|---|
| chicken_cage | 单笼一鸡，笼 0.80 × 0.70 × 0.60 m，简单凸代理 | 本轮一个笼、一只鸡，默认入笼。以一个订单货物实例验证运输、逃出、抓回、回笼与交付 |
| fish_tank | 空缸 0.90 × 0.75 × 0.65 m，简单凸代理 | 检查实际独立重击、裂纹与玻璃破碎，按当前配置计算品质 |
| bomb | 直径 0.65 m 的球形外观与球形代理 | 验证滚动、惯性、推拖、偏载和凝胶固定 |

试装用上述三件样例。首关最终清单、空缸折价和三货品质规则待确认，质量、运费及碰撞阈值待标定。运行态总件数、总质量、满品质运费和工资按实际订单清单计算。旧木箱、圆桶、重物作为独立回归样本。分别验证空舱四人、试装加三人、双人协作时第三人避让，并对照合理凝胶固定、左右偏载、高重心及自由货物，记录实际通行和装卸。

## 3. 车货物理、门闩和凝胶

E 读取 D 提供的人物状态与各自抓取目标，在同一权威物理步计算每人作用。输入按回合、玩家和输入流保留最新，多个抓点的力与力矩相加。释放、掉线和超时只解除当事人，受车承载的步行人物与座位乘员按身份去重。诊断总质量与实际刚体质量分栏，凝胶计重方式待确认。

E 按契约第 3、4.1 节管理独立鸡、笼体与笼门。`CargoId` 对应一个订单货物及默认笼体，`ChickenEntityId` 仅在鸡实际离笼后作为独立抓取目标。E 按 `TargetEntityId` 裁决每个实体最多两人，每名玩家同一时刻最多抓持一个实体。两人抓笼时第三人可抓离笼鸡。`ReadParticipants(cargoId)` 按原 `CargoId` 汇总两实体的参与记录。离笼更新 `ChickenCondition.InCage`、鸡的姿态和 `ConditionRevision`，订单维持原状态。`RequestReturnChickenToCage` 核对条件版本和实际抓持，成功时同次提交入笼、姿态与抓持清理。订单件数、清单质量和运费按原 `CargoId` 计一次。物理载荷按实际承载实体统计，鸡质量已并入笼体时计合并值，分离或换手后按实体身份去重。

E 实现 `RequestSetCageDoor`，按 `CargoId` 找到笼门并校验权限、实际可达及 `CageDoorRevision`。成功开合更新 `CageDoorOpen`、`CageDoorRevision` 与快照。回笼和笼门请求沿用 `CommandResolved`、`SnapshotChanged` 和现行去重规则。鸡行为限单鸡基础逃出与找回，具体触发、行为参数、抓回与回笼操作，以及是否须开门由 B 确认。[API 第 4.1 节](../API与联调契约_v0.2.md#41-车辆门闩与货物状态)

平稳行驶可在后舱独立步行、抓扶及操作胶枪。完整重摆大件与调整受力结构依稳定性配置，车速、相对速度及角速度阈值待标定。巡航按当前前进速度，W 保持目标，A/D 转向，S 或手刹同次输入取消。司机失联清巡航和占座并安全制动。后门门闩独立于门扇，按合法操作或飞车党实际干扰改变状态。E 将 A 的门闩挂点映射为 RearLatch，向 D/C 提供 DoorSnapshot 与 RearLatchChanged。

货物固定采用独立胶块、黏性接点与弹性约束。每人一把独立枪，E 确认发射时扣一单位并按当前枪颜色生成同尺寸胶块。胶块可彼此连接，各自保持身份、体积和颜色。回收归执行者的枪，重射用该枪颜色。用物理约束实现弹性、阻尼与回弹，释放后按剩余连接及实际运动连续受力。容量、初始量、尺寸、射程、强度、连接数量/距离和过载处理采用灰盒待标定或待确认配置。

| 步骤 | E 权威行为 |
|---|---|
| 收到操作 | 用 Key 校验回合与发送者，查重，再确认 GunId 归属和 ExpectedGunRevision。发射重验瞄准与命中，回收重验 TargetGelId、视线和距离 |
| 发射 | 一次提交扣 1 单位、创建胶块并登记有效连接。有效未附着块保留回收资格 |
| 预留回收 | 锁定目标，按 StoredUnits + ReservedRecoverUnits 检查容量。满枪 GelGunFull，目标被处理 GelBusy，已回收 GelAlreadyRecovered |
| 成功回收 | 一次提交移除该块及相关约束、完成预留、回收者枪加一单位，返回确认并下发同版本快照和事件。其它连接继续生效，再发用当前枪颜色 |
| 中断与重连 | 回收取消或掉线释放未提交锁及预留，重连恢复确认库存。发射者掉线后仍可回收其胶块 |
| 其他异常 | 破碎、交付与越界有序清理失效连接，保留可回收身份。重试从同一快照恢复枪内单位与世界胶块，避免同一次请求重复扣/返单位 |

胶块与连接数量采用有限且可配置的预算，回归记录实际耗时。D 负责瞄准、操作上下文和画面反馈，E 复核目标并返回可执行结果。键位、胶枪与持货切换、目标白名单、表现时长和过载仍按待确认事项处理。[API 第 4.2 节](../API与联调契约_v0.2.md#42-凝胶请求快照与反馈)

## 4. 订单、路线、燃油与恢复

准备装货不计时。司机确认出库生成唯一订单并起钟，运输、选路、应对、恢复、加油和卸货计入用时。校验交付区域、外部凝胶约束已解除、无抓取和实际稳定，按实例锁定品质，只确认一次。留在交付实例上的胶块保持独立可回收。被盗货物保留原 ID 和品质，追回后恢复订单状态。仍未追回时，达到下节点边界或明确放弃后确认丢失。订单货均终态后结算，零秒进入迟到。起始 720 s、扣薪档长、金额和封顶是灰盒待标定种子，按实际配置计算，实发最后四舍五入到整数分。

E 分别校验本单鸡与配套笼体实际进入室外收货区、稳定、解除抓取与外部凝胶约束。笼体以实际卸下后的合格状态判定归还。两者均合格正常交付，空笼保持未交付，逃出及正式丢失沿用原 `CargoId`。仅鸡合格时，E 发布 `OrderSnapshot.ChickenDeliveryChoice`。处理 `RequestResolveChickenDeliveryChoice` 时重验权限、`expectedChoiceRevision` 和现场条件。返回取笼或明确取消则结束本次选择并保持未交付。有效订单内选择失效时以 `CommandResolved` 返回 `StateChanged`，快照提供当前确认状态。

确认只交鸡时，E 在同一提交中写入 `Delivered`、该次 `PackagingFeeFen` 和 `ChickenCondition.CageLeftInLevel`，关闭选择并发布一次 `CargoDelivered`。费用按同轮同单同 `CargoId` 记录一次，重传返回原结果，其他并发请求按最新版本裁决。结算单列费用，从按既有品质和迟到规则计算的工资中扣除，`NetPayFen` 最低为 0。包装扣费独立于鸡的品质及丢失，逃出对品质和工资的影响待 B 确认。

只交鸡的展示及碰撞清理作用于鸡。笼体按 `CageLeftInLevel` 保持在原位置，继续碰撞、有效抓持、约束与实际车载计重。其后笼体移动或到达收货区时保持原终态和费用。进入下一关时清理本关标记的未归还笼及对应失效关联，再按下一关配置生成货物。本关 `RequestReset` 按关前快照恢复原有鸡、笼体、待选状态与费用，处理新回合及旧请求。断线重连恢复有效选择或已确认结果。[API 第 6 节](../API与联调契约_v0.2.md#6-订单路线与结算)

E 按 B 确认的八节点拓扑、连线和事件标签布置实际路线，使用 A 提供的建筑外观、道路模块和道具组装场景。发货仓库室外装货与签单，补给节点 E 室外加油，终点 T 的室外收货区统一交付。预选与锁定检查当前节点、司机资格、停车及 RouteRevision，所有分支可抵终点，路线油量估算使用同一油耗配置。[A 美术交接](A_3D美术与动画.md)

燃油采用实际行驶或怠速状态消耗，熄火耗量为 0。加油按请求量、剩余容量与可负担量确定实际升数，在一个提交更新钱包和油量并发收据。加油价格、注入精度、耗时及服务阈值待标定。重复、满油、并发与中断按 API §7 处理。

翻车和卡住提供单人基础恢复。恢复按实际承载与胶连处理随车人货，保留订单、品质和库存，由当前权威端按同一确认版本下发车体、随车人货与恢复结果。缺油或无钱可走受控援助或关前重试，条件、油量、冷却、落点和时间代价待验证。重试增加 RoundEpoch，恢复同一准备快照内的人车货、钱包、油、枪、胶块与连接及随机种子，清旧会话输入与事件。

## 5. 事件与翻车

| 测试入口 | E 要交付的实际行为 |
|---|---|
| UFO | 可识别预警及环境吸牛，实际车体升力或有效重力变化影响轮载、抓地和车内人货，减速、路线选择或驾车脱离有效 |
| 龙卷风 | 清晰风向和预警，实际横向力或侧倾，驾驶避让、主动离开或利用遮蔽，结束撤销该事件外力 |
| 骑牛飞车党 | 可观察的接近、门闩尝试、可达后取松散货、拖走与离场。检查门闩、抓持和有效连接，每次最多一件。驾驶、关门和凝胶保护分别可行，喇叭可干扰接近 |
| 物理翻车 | 实际驾驶、载荷、道路导致侧躺及四轮朝天，人货受力。用独立事故场景确认单人可恢复并继续运送 |

三个特殊事件各有可独立进入的测试入口，使用 Warn → Active → Recovery → Resolved，时序、次数和受力按配置标定。事件取消清该事件外力、临时目标与声音，保留已确认货物、门闩和有效玩家胶连。测试包含使用和不用喇叭。三个事件复用 A 的基础母牛模型，骑牛飞车党使用独立配饰。正常运输按选路和节奏调度，留平稳路段。扩展范围见主设计第 13.2 节。

## 6. 独立运输测试场与首次联调

D/E 从同一 Git 基线各开分支并记 SHA。E 在共同基线接入 B 确认的共享 C# 声明，统一维护 who-sent-this-guy/shared/contracts、正式主场景和工程级设置。E 用 Codex Agent 交独立运输测试场，目标入口为 who-sent-this-guy/tests/cargo_transport/transport_test.tscn。A 静态建模期间先用现有模型或几何占位，通过临时操作调用真实服务，记录驾驶、装货、凝胶等测试入口及预期结果。

1. 从正式 IVehicleService 与 IPhysicsObjectService 入口完成驾驶、抓取搬运和装货，模拟玩家调用相同验证流程。用测试配置核对鸡逃出后仍可找回、抓持和回笼、空笼保持未交付，以及两人抓笼加第三人抓离笼鸡、同一实体拒绝第三名参与者、笼内鸡拒绝独立抓取。调用 RequestSetCageDoor 验证开合、同版本并发、旧版本拒绝及同一请求重传。用 RequestReturnChickenToCage 确认回笼与解除抓持在同一提交内完成。
2. 调用 RequestFireGel、RequestRecoverGel，核对物理连接、库存前后值、回收者颜色与重射。不同玩家 ID 各绑自己的枪，向同一 TargetGelId 发两条独立请求，记录一次成功、一次 GelBusy 或 GelAlreadyRecovered、一个单位返还和相关连接清理。另跑满枪、重传、并发和回收中断。
3. 首次联调只接 D 的回收操作。D 角色按测试回收键，E 一次提交拆真实胶块和连接并给回收者加一单位，D 用确认状态刷新 HUD。随后复测满枪和双人抢收。

正常主场景目标为 who-sent-this-guy/scenes/graybox_delivery.tscn。运输沿用 features/cargo_transport/，订单路线、燃油与事件分别放 delivery_flow/、economy/、incidents/，相对 features/。E 统一接入共享类型、C# 工程设置和正常入口，提供实际构建与启动方式。场景用实际清单生成货物和 1～4 人入口，包含手册、室外装货与签发点、室外收货区、真实门洞、斜板、合法岔口、安全恢复点、室外加油位及事件作用区。

## 7. 正式联机

单机装运卸闭环通过后，由 E 接正式建房、连接和离开、房主端校验、快照与事件同步、输入投递和断线恢复。D 在此期间可用同一接口的模拟状态验证房间及队友界面。E 负责稳定玩家 ID、请求去重、版本分发、抓取与座位断线清理、重连确认快照和房主退出处理。正式房间由房主端裁决，D 根据确认状态呈现。网络传输方案依灰盒待 B 评审，回归时记录实际方案与测试条件。[API 并行开发约定](../API与联调契约_v0.2.md#11-de-并行开发约定)

## 8. 验收与五条线

- 交实际几何与场景记录，覆盖确认比例、后门门闩与后斜板，单人三类货物装卸、双人力贡献和载荷去重。
- 交凝胶发射与换色、跨玩家回收、满枪、抢收、重传、回收中断、越界、交付与回合重置证据，核对胶量、实体和连接同次更新。
- 交单机送货闭环、迟到边界、分支可达、失物与单次结算、燃油和加油并发、缺油与恢复记录。

- 交三个事件及独立物理翻车测试，记录作用、单人应对、失败、取消与继续运输。按 C 的音频交接用确认状态验车辆和货物位置声、事件与加油循环及回收中断清理。实测物理帧耗时和胶连、背景表现预算。
