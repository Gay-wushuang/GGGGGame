# E Agent 工作规范

B 指派 E 任务时使用 Codex，在 E 的独立工作树中开发并提交，以 E01～E09 为范围。开工前读 [通用规范](../../AGENTS.md)、[E 原交接单](E_独立功能实现.md) 与 [E 独立验收清单](E_开发与验收清单.md)。

## 工作目录与职责

工程目录为 `who-sent-this-guy/`。功能包为 `features/cargo_transport/`、`features/delivery_flow/`、`features/economy/` 和 `features/incidents/`。E 的测试目录为 `tests/cargo_transport/`。

- 独立测试场目标入口为 `who-sent-this-guy/tests/cargo_transport/transport_test.tscn`。
- 正常主场景目标入口为 `who-sent-this-guy/scenes/graybox_delivery.tscn`。

| 任务 | E 的职责 |
|---|---|
| E01～E03 | 车辆、座位、门闩、货物实体与受力、凝胶库存与连接 |
| E04～E05 | 路线和场景组装、订单与结算、燃油、钱包及加油交易 |
| E06～E07 | 三个事件、世界音频、物理翻车和异常恢复 |
| E08～E09 | 正式建房与连接、房主裁决、同步与断线处理、工程集成及测试交付 |

E 负责接入共享声明、主场景和公共工程设置。共享 API 变化须经 B 确认。禁止修改 D 的人物、镜头、玩家输入、HUD、界面、玩家功能包及独立测试场。

## 权威服务与独立开发

- 按已确认的 `DeliveryGame.Contracts` 实现会话与权威业务服务。使用契约中的回合、请求键和版本校验请求并去重。按同次权威提交发布实体、库存、约束、订单或交易的确认状态和事件。[API v0.6](../API与联调契约_v0.2.md) · [共享 C# 契约](../../who-sent-this-guy/shared/contracts/)
- D 模块可用之前，使用占位资源、模拟玩家 ID 和临时按键或脚本。驾驶、抓取、凝胶等经正式接口进入本地权威实现。用不同玩家与请求键验证抢收和并发，记录初始状态、确认结果和实际变化。
- D 的人物与输入模块就绪后通过接口接入。正式联机方案、玩法与经济的待定项由 B 决定。测试配置、参数种子及占位条件写在记录中。

## 联调与交付

1. 先在 E 场景内完成独立自测。首次联调提供真实胶块、连接、可用库存和 `IGelService` 确认结果。D 按回收键后，验证同次移除胶块和连接、回收者库存增一以及 HUD 采用同一确认版本。继续验满枪、抢收与重传。[API 联调顺序](../API与联调契约_v0.2.md#11-de-并行开发约定)
2. 接入正常场景完成单机装运卸后，按 B 评审方案接正式联网。E 提供房主和客户端可复跑的会话、状态同步及恢复证据。
3. 在本方分支自测、提交和发 PR。按 E 清单附真实服务入口、参数、请求与快照对照，以及测试失败复现。E09 记录自动化、运行与互审复测，B 按 E 的证据验收。[E 开发与验收清单](E_开发与验收清单.md)
